## Что это

P2P-обмен скинами CS2 в Telegram: привязка Steam и Trade URL, инвентарь с картинками и
ценами, доска объявлений с каталогом по разделам, сделки с двумя подтверждениями и
ссылкой Steam Trade с предзаполненными скинами, оценки и админка. Всё то же живёт в
Telegram Mini App.

## Модель данных (кратко)

- `users` — Telegram-профиль, Steam: `steam_id`, `steam_persona`, `steam_avatar_url`,
  `steam_profile_url`, `steam_trade_url`, `steam_trade_partner`, `steam_trade_token`,
  `inventory_synced_at`, `rating`, `trades_count`, `is_banned`
- `items` — инвентарь: `steam_asset_id`, `market_hash_name`, `class_id`, `instance_id`,
  `rarity`, `exterior`, `image_url`, `icon_url`, `price_steam`, `is_tradable`, `synced_at`;
  уникальный индекс `(owner_id, steam_asset_id)`
- `offers` — объявления: `items_offered` (JSON id предметов), `wanted_name` (скин из
  каталога), `items_wanted` (свободный текст), `status` (active / in_trade / completed /
  cancelled), `description`
- `trades` — сделки: `buyer_id`, `seller_id`, `offer_id`, `status` (pending → confirmed →
  in_escrow → holding → completed / cancelled), отметки `buyer_confirmed_at` /
  `seller_confirmed_at`, `buyer_completed_at` / `seller_completed_at`, `finalize_at`
  (когда сделку можно считать окончательной: второй «Получил» + 7 дней)
- `trade_items` — какие предметы кто отдаёт (`from_user_id` → `to_user_id`)
- `ratings` — оценки 1–5, уникальность `(trade_id, from_user_id)`
- `skins` — каталог CS2: `market_hash_name`, `price_text`, `price_value`, `icon_url`,
  `category`, `weapon`, `rarity` (слаг CS2: consumer … covert, rare, contraband)
- `disputes` — споры по сделкам: причина текстом, статус, решение админа; открытый спор
  на сделку только один (частичный уникальный индекс)

## Как устроены ключевые потоки

**Инвентарь.** Берётся из публичного `steamcommunity.com/inventory/<steamid64>/730/2` с
пагинацией: имена, теги (редкость, износ, тип), хеши картинок. API-ключ не нужен, инвентарь
должен быть открыт. Торговый кулдаун определяется по `owner_descriptions`
(«Tradable After …», «Обмен возможен после…») — такие предметы сохраняются с
`is_tradable = 0` и не попадают в офферы. `ItemRepository.sync` делает upsert по
`(owner_id, steam_asset_id)` и удаляет то, что исчезло из Steam.

**Профиль Steam.** `ISteamUser/GetPlayerSummaries` по `STEAM_API_KEY` — имя, аватар, ссылка.
Trade URL парсится в `partner` + `token` и хранится нормализованным.

**Каталог.** Импорт из Steam Community Market (`/market/search/render/`, страницы по факту
~10 позиций, пауза 2 с, при 429 пауза 45 с). Классификатор `utils/skin_categories.py`
раскладывает по категориям (винтовки, снайперские, ПП, пистолеты, тяжёлое, ножи, перчатки,
агенты, zeus, стикеры, граффити, музыка, кейсы) и определяет оружие; понимает префиксы
`StatTrak™` и `Souvenir`. Каталог пополняется ещё и при синхронизации инвентаря.

**Редкость каталога.** `skins.rarity` хранит канонический слаг. Откуда берётся: цвет и
тип предмета из Steam Market при импорте (`asset_description.name_color` / `type`), теги
инвентаря при синхронизации (`rarity_slug` понимает русские и английские формы), а старые
записи заполняет `scripts/import_rarities.py` из датасета CSGO-API (на рабочей базе закрыл
2012 записи из 3165). API отдаёт уже слаг, поэтому цвета совпадают на всех экранах.

**Каталог «на обмене».** Основная вкладка каталога показывает только скины, которые реально
можно получить: они выставлены в активных объявлениях доски. Данные — `skins.available_items`
(`offers` → `json_each(items_offered)` → `items`, группировка по имени скина, счётчики
`offers` и `owners`); фильтры и дерево разделов считаются по тому же набору. Вторая вкладка —
весь Steam-каталог (`skins.list_items`), он нужен шагу «хочу» и фильтрам по износу, цене и
StatTrak.

**Поиск «хочу».** `utils/skin_query.py` разбирает свободный текст: синонимы и русские
названия («асимов» → Asiimov, «керамбит» → Karambit, «катовице» → Katowice, «нож» → ★),
транслитерация, износ кодами (FN/MW/FT/WW/BS, «мв», «фт»), цена («до 100$», «500 баксов»),
StatTrak. `services/skin_search.py` ищет по шагам: с износом и ценой → без цены → без
износа → без категории ★ → fuzzy по `difflib`, причём в названии обязан быть якорь
(самое длинное слово запроса), чтобы не подсунуть случайный скин.

**ИИ-фолбэк «хочу».** Если локальный матчер не нашёл ничего (включая запросы, которые
локально не разбираются вовсе), текст уходит в LLM через OpenAI-совместимый
`/chat/completions`, ответ строго проверяется по схеме
`{weapon, market_hash_name, exterior, max_price, stattrak}` и превращается в `SkinQuery`,
после чего поиск повторяется по каталогу уже с этими полями. Фолбэк включён только при
непустом `LLM_API_KEY` (иначе один info в лог при старте, HTTP не вызывается); сбой
провайдера — таймаут, 5xx, 4xx, невалидный JSON — возвращает прежний результат поиска,
ретрай не больше одного (только на временные сбои). Ключ и текст запроса не попадают
ни в логи, ни в ответы. Настройки: `LLM_API_KEY`, `LLM_BASE_URL` (по умолчанию
`https://api.openai.com/v1`), `LLM_MODEL` (`gpt-4o-mini`), `LLM_TIMEOUT` (10 с).

**Создание объявления (3 шага, бот и Mini App).** 1) выбрать свои скины (нумерация 1..N
совпадает с `/inventory`, настоящие id спрятаны в состоянии FSM); 2) описать желание
словами, бот ищет в каталоге; 3) подтвердить черновик. Название собирается автоматически:
«★ Ursus Knife | Ultraviolet → AWP | Asiimov».

**Сделки (актуальная модель).**
1. Доска показывает объявления с карточками «отдаю / хочу».
2. Второй человек жмёт «🤝 Предложить обмен», выбирает свои скины из инвентаря и отправляет
   встречное — в сделку попадают предметы обеих сторон.
3. Подтверждение инициатора ставится автоматически (`buyer_confirmed_at` в момент создания).
4. У автора объявления это видно во «📥 Входящие предложения»; он подтверждает
   (`seller_confirmed_at`).
5. Когда подтвердили оба — статус `in_escrow` и появляется кнопка **«🔗 Steam Trade»**:
   ссылка на Trade URL контрагента с параметром `items` (JSON скинов этой стороны), поэтому
   предметы уже стоят в окне обмена.
6. После обмена каждая сторона жмёт «📦 Получил». Когда отметили оба — сделка идёт не в
   `completed`, а в `holding`: полученные CS2-предметы 7 дней под Steam Trade Protection
   (нельзя передать или продать), и всё это время отправитель может отменить трейд. В карточке
   сделки видно предупреждение и дату `finalize_at` = момент второго «Получил» + 7 дней
   (в карточке — `01.12.2026 12:00 UTC`).
7. `holding` → `completed` без демона: срок проверяется при каждом чтении сделки
   (`services/trades.finalize_due`), `TradeRepository.finalize` закрывает только ту сделку,
   у которой `finalize_at <= now`, и возвращает True ровно одному вызову — поэтому счётчики
   сделок и статус объявления обновляются один раз. `completed_at` = `finalize_at`.
8. Оценка 1–5 и рост `trades_count` доступны только в `completed`; в `holding` бот и Mini App
   отвечают датой, когда оценка откроется.
9. Отмена до получения скинов (объявление возвращается на доску) и отдельная ветка для
   `holding`: контрагент откатил трейд в Steam → кнопка «↩️ Трейд отменён», сделка уходит в
   `cancelled`, счётчики и оценки не меняются.
10. Если обмен пошёл не так, участник жмёт «⚠️ Открыть спор» (в боте и в Mini App),
   пишет причину текстом — создаётся запись в `disputes`, админ (8851272459) и вторая
   сторона получают уведомление. Открытый спор на сделку только один (уникальный индекс
   `idx_disputes_open_trade`), кнопка исчезает, пока спор не решён через /resolve.

**Объявление живёт до обмена.** Доска, каталог «на обмене» и подбор видят объявления в
`active` **и** `in_trade`: раньше объявление исчезало, как только кто-то предлагал обмен.
Предложить обмен можно и по объявлению в сделке — обмены независимы. Объявление становится
`completed`, когда обе стороны нажали «📦 Получил» (`services/trades.settle_after_receipt`),
а не в момент открытия сделки и не после 7-дневного Trade Protection. Если трейд откатили в
Steam, объявление возвращается в `active`.

**Подбор обменов.** `GET /api/offers?match=1` — только объявления, где хотят скин из
инвентаря зрителя (`items.owner_names` + `offers.active_for_names`); в карточке поле
`match` рисует бейдж «🤝 ваш скин». При публикации объявления бот пишет владельцам нужного
скина (`offers.owners_wanting`, до 20 человек, кроме автора) — писать можно только тем, кто
уже начинал диалог с ботом.

**Mini App.** `src/webapp/app.html` — нижняя навигация из пяти разделов плюс «Ещё»: Инвентарь,
Каталог, Доска, Сделки, Профиль, а в листе — Создать, Мои, Рейтинг, Админ (только для
8851272459), Помощь. Авторизация: `initData`
проверяется HMAC-SHA256 от `BOT_TOKEN` (`utils/telegram_auth.py`), без подписи `/api/*`
отвечает 401. Админка закрыта и в интерфейсе, и на сервере.

**Оформление Mini App.** Всё инлайн, без CDN (кроме обязательного `telegram-web-app.js`).
Палитра — CSS-переменные: фолбэки для светлой и тёмной темы в `:root` и
`prefers-color-scheme`, а в Telegram значения перекрываются из `themeParams`
(`bg_color`, `secondary_bg_color`, `text_color`, `hint_color`, `button_color`,
`button_text_color`), событие `themeChanged` перекрашивает на лету. Карточки скинов красятся
по редкости: полоса сверху и бейдж берут цвет из `items.rarity` (русские и английские
названия редкостей, включая «★» и контрабанду). Инвентарь, каталог и доска при загрузке
показывают скелетоны с шиммером (`prefers-reduced-motion` его отключает), а не текст
«Загрузка…». Отступы и типографика — на токенах (`--sp-*`, `--fs-*`, `--r-*`).

**Скорость Mini App.** `/api/catalog`, `/api/catalog/tree` и `/api/catalog/items` кэшируются
в памяти веб-процесса (`catalog_cache.CatalogCache`) на `WEB_CACHE_TTL` секунд (по
умолчанию 60, `0` — выключено) и отдают ETag: повторный запрос с `If-None-Match` получает
304 без тела. Кэш живёт только в процессе, а корректность между процессами держит версия
каталога в `settings.catalog_version`: её поднимают импорт каталога
(`services/skin_catalog.py`) и синхронизация инвентаря (`services/inventory_sync.py`),
поэтому бот или CLI-импорт сразу сбрасывают кэш веб-процесса. Клиент складывает
загруженные страницы каталога в `Map` и на фоне предзагружает следующую.

**API Mini App:** `/api/me`, `/api/profile/steam`, `/api/profile/refresh`, `/api/inventory`,
`/api/inventory/sync`, `/api/catalog`, `/api/catalog/tree`, `/api/catalog/items` (весь Steam,
фильтры `wear`/`min`/`max`/`st`/`sort`), `/api/catalog/available` и
`/api/catalog/available/tree` (только то, что на обмене), `/api/offers` (GET доска с `q` и
`match=1`, POST создание), `/api/my_offers`, `/api/offers/{id}/accept|cancel|
delete`, `/api/trades`, `/api/trades/{id}/{confirm|complete|rollback|cancel|rate}`, `/api/trades/{id}/dispute`, `/api/rating`,
`/api/admin/{stats|users|ban|disputes|disputes/{id}/resolve}`.

## Инфраструктура и запуск (что где живёт)

- Bot API с домашней сети заблокирован провайдером. Рабочая схема на 25.11: подключённый
  Cloudflare WARP (`warp-cli status` → Connected) и пустой `TELEGRAM_PROXY` — бот ходит
  напрямую. Прежний Xray (VLESS `217.69.167.111:43000`) умер: REALITY-хендшейк не проходит
  ни с одним `serverName`. `TgWsProxy_windows` (127.0.0.1:1443) — MTProto-прокси для
  Telegram Desktop, HTTP/SOCKS не отдаёт и для Bot API не годится.
- Порядок запуска: `python -m web_app` (8080) → `cloudflared tunnel --url http://localhost:8080
  --logfile cloudflare.log` → `scripts/refresh_webapp_url.py` (берёт последний живой адрес)
  → `python -m bot.main`. Бот читает `WEB_APP_URL` только при старте, поэтому после
  перезапуска туннеля его нужно перезапустить.
- Живой бот строго один: два поллера дают `TelegramConflictError` и штраф на токен.
- Mini App требует HTTPS: используется `cloudflared tunnel --url http://localhost:8080`,
  адрес попадает в `WEB_APP_URL` (меняется при каждом перезапуске туннеля —
  `scripts/refresh_webapp_url.py`).
- `start_all.bat` поднимает всё: Xray → веб-приложение → туннель → обновление `.env` → бот.
- Резервные workflow: `ci.yml` (ruff + pytest), `bot-live.yml` (поллинг на раннере, только
  вручную), `deploy.yml` (деплой на VPS, только вручную).

## Грабли, на которые уже наступали

- **Несколько поллеров одновременно** → `TelegramConflictError` и штраф на токен. Всегда
  проверять, что запущен ровно один `bot.main`, и не включать расписание `bot-live`
  параллельно с локальным ботом.
- **Общий IP + Bot API** (WARP, раннеры GitHub) → `429 Flood control`. Домашний IP вообще
  блокируется провайдером, поэтому нужен именно Xray/свой прокси.
- **Токен в публичном репозитории** был подобран и использован для спама. `.env` в
  `.gitignore`, `.env.example` пустой, токены — только в `.env` и секретах GitHub.
- **Схема только в миграциях**, `models.py` удалён. `init_database` создаёт каталог базы.
- **HTML в Telegram** требует `parse_mode=HTML` (было забыто — теги выводились текстом).
- **Сломанный JS в Mini App** = «вечная загрузка»: страница грузится, но ничего не работает.
  Защита — тест, который парсит встроенный скрипт через esprima (`tests/unit/test_mini_app.py`).
- **Дубли обработчиков** на один callback/команду → работает только первый зарегистрированный
  роутер.
- **Конкретный маршрут API должен регистрироваться раньше общего**: aiohttp берёт первый
  совпавший, поэтому `/api/trades/{id}/dispute` объявлен до `/api/trades/{id}/{action}`.
- **Бот в веб-процессе** — только для уведомлений (`app[BOT_KEY]`): если он не создан,
  спор всё равно открывается, но уведомления не уходят (в логе warning).
- **id предмета** — это `items.id` из базы (не Steam asset id). Нумерация в интерфейсе
  отдельная, 1..N, и совпадает между `/inventory` и шагом выбора скинов.
- **Сделка не становится `completed` по двум «Получил»** — она идёт в `holding` на 7 дней
  Trade Protection. Переход делает не задача-демон, а первое чтение сделки после
  `finalize_at`; поэтому любой новый экран сделок должен звать `services/trades.finalize_due`,
  иначе сделка навсегда останется `holding`. Счётчики начисляет только тот вызов, чей
  `UPDATE` реально сменил статус (иначе два чтения подряд удвоят `trades_count`).
- **Кэш каталога живёт в памяти веб-процесса**, поэтому прямой `INSERT` в `skins` мимо
  `import_catalog`/`sync_inventory` его не сбросит: писать в каталог только через сервисы
  (они поднимают `settings.catalog_version`) либо ждать `WEB_CACHE_TTL`.
- **Объявление закрывается по обмену, а не по сделке.** Доска и каталог «на обмене» смотрят
  `active` **и** `in_trade`; `completed` ставится в `settle_after_receipt` (два «Получил»), а
  откат трейда возвращает объявление в `active`. Не возвращать проверку «только active» —
  на этом уже потеряли объявления до обмена.
- **`cloudflare.log` накопительный**: в нём лежат адреса от прошлых запусков, и первый из них
  мёртвый. `scripts/refresh_webapp_url.py` берёт последний и проверяет `/health`.
- **Bot API и прокси.** Домашний провайдер блокирует Bot API; рабочий путь на 25.11 —
  Cloudflare WARP плюс пустой `TELEGRAM_PROXY`. Xray (VLESS 217.69.167.111:43000) не
  поднимает REALITY-хендшейк, `TgWsProxy` (127.0.0.1:1443) — MTProto-прокси для десктопа и
  HTTP/SOCKS не отдаёт. WARP тоже делит IP с другими — при `429 Flood control` ждать, а не
  перезапускать поллер в цикле.
- **Бот читает `.env` один раз при старте**: после смены `WEB_APP_URL` или `TELEGRAM_PROXY`
  его нужно перезапустить, иначе кнопка «Приложение» ведёт на старый адрес.
- **`token` в git credential helper без scope `workflow`**: правки `.github/workflows/*.yml`
  не пушатся (`refusing to allow ... without workflow scope`). Нужен токен с этим scope или
  ручная правка через веб.

## Редкость каталога

`skins.rarity` (миграция 009) хранит канонический слаг редкости (consumer … covert,
rare, contraband). Откуда берётся: цвет и тип из Steam Market при импорте
(`asset_description.name_color` / `type`), теги инвентаря при синхронизации
(`rarity_slug` понимает русские и английские формы), а исторические записи
заполняются скриптом `scripts/import_rarities.py` из открытого датасета CSGO-API:

```
python scripts/import_rarities.py --db data/bot.db            # отчёт, dry-run
python scripts/import_rarities.py --db data/bot.db --apply    # записать
```

API Mini App отдаёт редкость уже слагом (`rarity_slug`), поэтому цвета в каталоге
одинаковые на всех экранах.

## Фильтры каталога и поиск по доске

`GET /api/catalog/items` принимает `sort` (price_asc по умолчанию, price_desc, name, new),
`wear` (fn/mw/ft/ww/bs), `min`/`max` (цена в долларах), `st=1` (только StatTrak™).
Счётчик учитывает все фильтры, сортировка — только порядок. Ключ кэша включает фильтры.

`GET /api/offers` принимает `q`: поиск по токенам в названии, желаемом скине, свободном
описании желания и описании объявления.

Mini App: полоса фильтров под поиском (износ, цена от/до, сортировка, StatTrak™) и
строка поиска на доске; заголовок каталога показывает «Найдено N из M».

## Надёжность веб-слоя

- Любое необработанное исключение в API отвечает `{"error": "internal", "request_id": …}` с кодом
  500 и заголовком `X-Request-Id`, а не HTML-страницей; `X-Request-Id` из запроса переиспользуется.
- Каждый запрос логируется строкой «метод путь -> статус за N мс (request_id=…)». Тело запроса и
  initData в лог не попадают.
- `/health` проверяет базу: `{"status": "ok", "db": "ok", "migrations": N}`, при сбое базы — 503 и
  `degraded`.
- Ограничение размера тела запроса — 1 МБ (`client_max_size`).

## Бэкапы и запуск

- `scripts/backup_db.py` — онлайн-копия базы в `backups/` (sqlite backup API) с ротацией:
  `--keep` (по умолчанию 7), `--list` для просмотра. Копию снимают при работающем боте.
- CI проверяет ещё и `scripts/` и собирает docker-образ, а также импортирует в нём `web_app`.
- `docker-compose.yml` поднимает два сервиса: `bot` (поллинг) и `web` (Mini App и API на 8080)
  с healthcheck на `/health`.

## Подбор объявлений под инвентарь

- `GET /api/offers?match=1` отдаёт только объявления, где хотят скин из инвентаря зрителя.
- На каждой карточке доски поле `match` — имя своего скина, который подходит под «хочу»
  (в Mini App это зелёный бейдж «🤝 ваш …»).
- При публикации объявления бот пишет владельцам нужного скина (до 20 человек, кроме автора):
  «Ваш скин ищут». Ошибка отправки не ломает публикацию.

## Каталог «на обмене»

Каталог по умолчанию показывает только то, что реально можно получить: скины из активных
объявлений доски. Источник данных — `skins.available_items` (join `offers` → `json_each(items_offered)`
→ `items`, группировка по имени скина, счётчики `offers` и `owners`).

- `GET /api/catalog/available` — скины на обмене: `category`, `weapon`, `q`, `sort`
  (`offers_desc` по умолчанию, `price_asc`, `price_desc`, `name`), пагинация.
- `GET /api/catalog/available/tree` — разделы и оружие только по обменным скинам.
- Вторая вкладка в Mini App — «Весь каталог Steam» (`/api/catalog/items`): он нужен шагу
  «хочу» при создании объявления и фильтрам по износу, цене и StatTrak.
- Карточка обменного скина показывает число предложений и кнопку «На доске», которая
  открывает доску с поиском по этому скину.

## Объявление живёт на доске до обмена

Доска и каталог «на обмене» показывают объявления в статусах `active` и `in_trade`
(`OPEN_OFFER_STATUSES`), а не только `active`. Раньше объявление исчезало, как только
кто-то предлагал обмен, хотя обмен ещё не состоялся.

- Принять объявление в сделке можно: проверка статуса пускает `active` и `in_trade`.
- Объявление становится `completed`, когда обе стороны нажали «Получил» (`settle_after_receipt`),
  а не в момент открытия сделки. Если трейд отменили в Steam, объявление возвращается в `active`.
- Подбор «подходят мне» тоже учитывает объявления в сделке.
